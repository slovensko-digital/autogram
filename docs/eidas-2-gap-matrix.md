# Autogram eIDAS 2.0: verifiable gap and test matrix

> **Branch scope:** this is a documentation-only branch. The trusted-list validation hardening and the three tests named in the text (SignatureValidatorTrustedListTest, TrustedListLiveSmokeTest, SignatureValidationPresentationTest) are delivered as a separate code change and are not present on this branch; those mentions describe that companion change.

**Assessment:** 3 October 2026. Companion to [the legal-obligation report](eidas-2-compliance-report.md). **Evidence types are deliberately separate:** source-code review, deterministic tests, an opt-in **live** trusted-list test, and legal/organisational facts. A successful test of a particular list or document is **not** a certification or a claim that every qualified signature is validated correctly.

### ETSI TS 119 101 V1.1.1, §8.2 — all signature-validation-process controls

This is a **conditional mapping for claiming the 2025/1945 reference-standard route**, not 23 independent new statutory obligations. `SVA` means signature validation application, `DA` the driving application. Source: [ETSI TS 119 101, §8.2, SVP 1–23](https://www.etsi.org/deliver/etsi_ts/119100_119199/119101/01.01.01_60/ts_119101v010101p.pdf). The table paraphrases rather than replacing the standard; **Unknown** means no complete evidence of the named control.

| Control | What to verify | Code/documentation evidence and status |
| --- | --- | --- |
| SVP 1–2 | Document supported formats, levels and restrictions; implementation matches documentation. | [`README.md`](../README.md#L1-L19), [`SignatureValidator.java`](../src/main/java/digital/slovensko/autogram/core/SignatureValidator.java#L215-L265); **Unknown** for complete levels, JAdES/legacy restrictions and test-backed accuracy. |
| SVP 3–5 | Document validation process, old-signature handling and actual default policy; control implementation against the documented process. | DSS calls from [`SignatureValidator.java`](../src/main/java/digital/slovensko/autogram/core/SignatureValidator.java#L72-L76); no versioned policy/conformance proof; **Unknown**. |
| SVP 6 | Check mandated signed elements/commitment types when the selected policy requires them. | No business-policy test matrix; **Unknown**. |
| SVP 7 | Document the default validation policy and configurable validation constants. | Country selector exposed in [`UserSettings.java`](../src/main/java/digital/slovensko/autogram/core/UserSettings.java#L38-L50); full DSS policy and freshness constraints not documented; **Unknown**. |
| SVP 8–9 | If policy OID in signature differs from applied policy, notify driving application/user (user-level recommendation in SVP 9). | No mismatch fixture or visible policy notice verified; **Unknown**. |
| SVP 10–11 | Select signed object, detached data, certificate, signature and policy as dictated by business rules; advanced user input is optional. | Document and multi-signature support in [`ValidationReports.java`](../src/main/java/digital/slovensko/autogram/core/ValidationReports.java#L70-L119); detached-data/policy cases **Unknown**. |
| SVP 12–13 | Offer human-readable summary/report and purported signer plus issuer and higher CA identification. | GUI summary, issuer and HTML report: [`GUIValidationUtils.java`](../src/main/java/digital/slovensko/autogram/ui/gui/GUIValidationUtils.java#L92-L135), [`SignaturesController.java`](../src/main/java/digital/slovensko/autogram/ui/gui/SignaturesController.java#L88-L121); higher-chain presentation/completeness **Unknown**. |
| SVP 14–16 | Provide signature, detached content and applied policy to validator. | Signed-document dispatch in [`SignatureValidator.java`](../src/main/java/digital/slovensko/autogram/core/SignatureValidator.java#L140-L155); policy/detached cases **Unknown**. |
| SVP 17–19 | Apply policy, fetch necessary validation evidence and have a reference time source. | OCSP/CRL and trusted-list sources exist ([`SignatureValidator.java`](../src/main/java/digital/slovensko/autogram/core/SignatureValidator.java#L87-L125)); policy, evidence freshness and time-source assurance **Unknown**. |

| SVP 22–23 | Make result, policy, signatory and known commitment accessible in UI. | GUI shows signer and result ([`GUIValidationUtils.java`](../src/main/java/digital/slovensko/autogram/ui/gui/GUIValidationUtils.java#L92-L135)); applied policy/commitment evidence **Unknown**. |

The same ETSI standard includes common controls (§§5–7) and signature-creation controls (§8.1, e.g. displayed-to-signed data integrity, signed-attribute display, key choice, signer consent, PIN handling and batch scope). **Do not infer full compliance from SVP controls alone**: perform a separate, licensed clause-by-clause review of relevant `UI`, `GSM`, `ISMS`, `PD`, `SCP` and `SSI` controls, mark conditional clauses explicitly and collect organisation-level evidence for security/release procedures. The device-certification exclusion in [Decision 2016/650, recital 7](https://eur-lex.europa.eu/eli/dec_impl/2016/650/oj/eng) does **not** waive the applicable application requirements.
