# Commission Implementing Regulation (EU) 2025/2531 — reference standards for qualified electronic ledgers

## Executive summary

This act establishes, under Article 45l(3) of Regulation (EU) No 910/2014 (eIDAS, as amended by [Regulation (EU) 2024/1183](eu-reg-2024-1183.md)), the **reference standards and specifications for the recording of electronic data in a qualified electronic ledger**. Its addressees are **providers of qualified electronic ledgers** (a qualified trust service) and, for the compliance presumption, supervisory bodies; the Commission commits to review the specifications. It is therefore an act about a **trust-service role Autogram does not occupy**: Autogram is a local desktop application, local API and CLI for signing and validating documents, is not a qualified trust-service provider and operates no ledger, blockchain, distributed-ledger or hosted document-processing service.

The act's only genuine touchpoints with Autogram are **Indirect interoperability references** in its technical annex: qualified-ledger providers must anchor data origin and integrity on advanced electronic signatures/seals based on qualified certificates made with **CAdES (EN 319 122-1)**, **XAdES (EN 319 132-1)** or **JAdES (TS 119 182-1)**, must order records with hash lists/hash trees or qualified timestamps, and must hold signing keys in a certified cryptographic device. Autogram's inspected creation path supports XAdES, CAdES and PAdES through DSS, defaults to SHA-256, and can attach a remote timestamp (`BASELINE_T`), but it has **no JAdES branch**, no hash-list/hash-tree ordering, no ledger-report generation and no evidenced certified cryptographic device. None of that is a breach of this act, which binds ledger providers, not local-signing software publishers. The technical rows below are recorded as **Indirect / Unknown** or **None / Ignored** accordingly; "Unknown" means the standard's applicability to a qualified-ledger role is not established or conformity was not proven, never that an obligation was breached.

Inspected evidence: [SigningJob.java](../../src/main/java/digital/slovensko/autogram/core/SigningJob.java) `createSignatureService` (lines 130–149, XAdES/CAdES/PAdES selection, no JAdES); [DssSigningParametersFactory.java](../../src/main/java/digital/slovensko/autogram/core/DssSigningParametersFactory.java) (lines 14–99); [SigningParameters.java](../../src/main/java/digital/slovensko/autogram/core/SigningParameters.java) (default `SHA256`, lines 58, 92–94); [UserSettings.java](../../src/main/java/digital/slovensko/autogram/core/UserSettings.java) `setTsaServer` (lines 361–375); [pom.xml](../../pom.xml) (DSS 6.5, lines 18, 43–49). A targeted search of `src/` found no qualified-ledger, ledger-report, consensus or hash-list/hash-tree code. Assessment/source access date **8 October 2026**; repository baseline **5ca91d5c**. Adopted **16 December 2025**, published in the OJ **17 December 2025**, in force **6 January 2026**.

## Evidence key

All source was inspected on 8 October 2026 at baseline `5ca91d5c`; no builds or tests were run, and source inspection is not a released-binary audit.

- **G1 — scope/organisation:** [README.md](../../README.md) (desktop signing/validation, local HTTP API and CLI) and the register [README](README.md) shared facts: no qualified trust-service provider role, no hosted document-processing service, no ledger operation. This establishes the reviewed boundary, not an exhaustive negative proof.
- **C1 — creation dispatch:** [SigningJob.java](../../src/main/java/digital/slovensko/autogram/core/SigningJob.java), `createSignatureService`, lines **130–149**: XAdES/CAdES select ordinary or ASiC services, PAdES its service; the default branch throws for any other form, so there is **no JAdES branch**. A timestamp source is set only for `BASELINE_T` (lines 146–147).
- **C2 — signature parameters:** [DssSigningParametersFactory.java](../../src/main/java/digital/slovensko/autogram/core/DssSigningParametersFactory.java), lines **14–99**: CAdES/XAdES/PAdES parameter objects; `setEn319122`/`setEn319132` toggles; no JavaScript-object/JSON signature construction.
- **C3 — digest:** [SigningParameters.java](../../src/main/java/digital/slovensko/autogram/core/SigningParameters.java), `buildParameters` line **58** and `getDigestAlgorithm` lines **92–94**, default to `DigestAlgorithm.SHA256`; [SigningKey.java](../../src/main/java/digital/slovensko/autogram/core/SigningKey.java), `sign`, lines **24–29**, likewise defaults to SHA-256. This shows a hash-size default, not hash-list/hash-tree ordering.
- **C4 — timestamps:** [UserSettings.java](../../src/main/java/digital/slovensko/autogram/core/UserSettings.java), `DEFAULT_TSA_SERVER` line **50** and `setTsaServer`, lines **361–375**, build a `CompositeTSPSource` from configured remote TSA URLs; [SigningJob.java](../../src/main/java/digital/slovensko/autogram/core/SigningJob.java), lines **146–147**. This proves configurable timestamp acquisition, not that a returned token is a **qualified** timestamp.
- **C5 — no ledger symbols:** a targeted search of `src/` for `ledger`, `blockchain`, hash-list and hash-tree/Merkle identifiers returned no qualified-ledger, distributed-ledger, consensus, ledger-report or ordering code. A negative search is a scoped result, not proof that no release could ever contain such code.
- **C6 — external token:** [SigningKey.java](../../src/main/java/digital/slovensko/autogram/core/SigningKey.java), lines **15–29**; [NativePkcs11SignatureToken.java](../../src/main/java/digital/slovensko/autogram/drivers/NativePkcs11SignatureToken.java), lines **26–55**: signing is delegated to the selected PKCS#11/keystore token. Use of an external token is not evidence of Common Criteria EAL 4+ or FIPS 140-3 level 3 certification.
- **D1 — DSS:** [pom.xml](../../pom.xml), lines **16–18** (`dss.version` **6.5**) and **43–49** (BOM import); the library provides XAdES/CAdES/PAdES/ASiC and validation, but library selection is not profile/specification conformity to the annex's fixed editions.
- **J1 — JAdES gap:** [eidas-2-gap-matrix.md](../eidas-2-gap-matrix.md) line 56 and [eidas-2-compliance-report.md](../eidas-2-compliance-report.md) line 50 record "no creation branch" for JAdES and unverified input support.
